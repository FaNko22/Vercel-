# بن الشريب — POS V2 Secure

نظام POS متعدد الفروع: Owner واحد، مدير لكل فرع، وكاشير صباحي وكاشير مسائي لكل فرع.

## الصلاحيات
- **Owner:** كل الصلاحيات، كل الفروع، إدارة المستخدمين والمنتجات والمخزون والتقارير وإلغاء/تعديل الفواتير.
- **Manager:** فرعه فقط، مراجعة المخزون والتقارير، فتح/مراجعة وإقفال الشيفت والمالية اليومية. لا تعديل/حذف فواتير ولا تعديل مخزون ولا إدارة مستخدمين/منتجات.
- **Cashier:** فرعه والشيفت المخصص له فقط، البيع وفتح شيفته. لا إدارة أو تعديل بيانات مالية.

## الأمان
الواجهة لا تتصل بجداول Supabase مباشرة. كل عمليات التطبيق تمر عبر `/api/pos` على Vercel، والـ service-role key يبقى Server-only. الـ PINs مخزنة bcrypt hash فقط.

## النشر على Vercel
أضف Environment Variables في Vercel:
- `SUPABASE_URL` = رابط مشروع Supabase
- `SUPABASE_SERVICE_ROLE_KEY` = Service Role Key (Server-only)
- `SESSION_SECRET` = قيمة عشوائية طويلة لا تقل عن 32 حرفًا

يمكن الإبقاء على `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` محليًا، لكن النسخة الآمنة لا تحتاجهما في المتصفح.

## قاعدة البيانات
في قاعدة جديدة شغّل الترحيلات بالترتيب: `01_setup.sql` ثم `02_audit_fixes.sql` ثم `03_secure_v2.sql` ثم `04_production_model.sql` ثم `05_restore_missing_actions.sql` ثم `06_shift_sequence_guard.sql`. في قاعدة قائمة بالفعل، خذ Backup ثم طبّق الملفات التي لم تُطبّق بعد بالترتيب نفسه.

الترحيل السادس يمنع فتح الشيفت المسائي قبل إغلاق شيفت الصباح لنفس الفرع وفي نفس يوم العمل بتوقيت القاهرة. بعد الترحيلات، اختبر الدخول والمبيعات والشيفتات قبل التشغيل الفعلي.
